## 模块 04：Monocle3 拟时序分析

### 核心概念

**拟时序（pseudotime）是什么？**
单细胞测序是一个"快照"：同一时刻测到处于不同分化阶段的细胞。如果分化过程连续，这些细胞在低维空间（UMAP）上会排成一条"路径"。拟时序分析把每个细胞投影到这条路径上，给出一个 0 到 1（或任意标度）的坐标——**它不是真实时间，而是"分化进度"的计算度量**。

**Monocle3 的三步逻辑：**
1. `learn_graph()`：在 UMAP 空间里用"反转图嵌入"（reversed graph embedding）拟合一棵主图（principal graph），即穿过细胞云团中心的一棵树；
2. `order_cells()`：指定起点（根节点，生物学上选 naive/干细胞样群体），沿树计算每个细胞到根的最短路径长度 = 拟时序；
3. 按拟时序着色，看哪个亚群在起点、哪个在终点。

**方向是人为定的**：算法不知道哪头是起点，必须结合生物学知识（naive T 细胞标记 TCF7/LEF1）指定根。方向反了不是 bug，是根选反了。

### 面试自测题

**Q1：拟时序分析能不能证明"耗竭 T 细胞是由效应 T 细胞分化来的"？**
> 答案要点：不能单独证明。拟时序是基于表达相似性的**计算推断**，提示分化路径存在；要下因果结论需结合其他证据（TCR 克隆型共享分析——GSE108989 原文正是用 STARTRAC 结合 TCR 谱系追踪佐证的）。表述时用"suggest/提示"。

**Q2：为什么选 naive T 细胞作为轨迹起点？方向反了怎么办？**
> 答案要点：生物学上 naive T 是 T 细胞分化的起始状态（TCF7/LEF1/CCR7 高表达），肿瘤内耗竭细胞是终末状态。方向反了的本质：order_cells 的根节点选错了。修法：把起点群改为 naive 亚群重跑 order_cells；画图层面也可对 pseudotime 取 max−x 反转，但逻辑上不如重选根干净。

**Q3：monocle3 和 Seurat 是什么关系？为什么要做对象转换？**
> 答案要点：两者是独立的分析框架，数据结构不同——Seurat 用 SeuratObject，monocle3 用 cell_data_set（基于 SingleCellExperiment 体系）。转换的本质是把三样东西搬过去：① 表达 counts 矩阵、② 细胞注释、③ 基因注释（必须有 gene_short_name 列）；另外把 Seurat 算好的 UMAP 坐标和分群结果塞回去，保证轨迹画在和主项目一致的 UMAP 上。Seurat v5 的 Assay5 多层结构是主要兼容坑，需先 JoinLayers。

### 常见报错

| 报错 | 原因与解决 |
|---|---|
| `unable to find an inherited method for ... 'Assay5'` | Seurat v5 对象直接喂给 monocle3。改用脚本里的"手动构建 cell_data_set"方式；或先 `JoinLayers()`。 |
| `function '...' not provided by package 'Matrix'` | Matrix 包升级后与 monocle3 二进制不兼容。重装 monocle3：`remotes::install_github("cole-trapnell-lab/monocle3")`；必要时先重装 irlba/igraph。 |
| GitHub 安装 monocle3 失败（编译错误） | Windows 缺 Rtools。装对应 R 版本的 Rtools 并加入 PATH；或试 `ref = "develop"` 分支。 |
| `order_cells` 报错/所有细胞 pseudotime 为 Inf | 根节点所在 partition 与部分细胞不连通（`use_partition=TRUE` 时不同 partition 互不连接）。检查 `plot_cells(cds, color_cells_by="partition")`；不连通的细胞无法被赋拟时序，属预期行为，解读时排除或单独分析。 |
| 找不到 ROOT_GROUP 对应的细胞 | 起点群名字写错。先 `unique(seu$celltype)` 确认实际取值。 |

## 模块 05：CellChat 细胞通讯分析

### 核心概念

**配体-受体（L-R）数据库**：CellChat 内置人工整理的 CellChatDB（人版约 2000+ 对互作），收录了分泌信号（如细胞因子）、细胞-细胞接触（如 PD-1/PD-L1、TIGIT/PVR）和 ECM-受体三类互作，且考虑了多亚基复合体（如 TCR 复合体）——受体是复合体时要求多个亚基都表达才算数。

**通讯概率的计算**：对每个 L-R 对，用"发送群的配体平均表达 × 接收群的受体平均表达"，经质量作用定律建模得到概率值；再用置换检验（打乱细胞标签重算）得到 p 值，筛出显著互作。最后把 L-R 水平结果汇总到通路水平（如 MIF 通路、TIGIT 通路）。

**网络的三种解读维度**：① 数量（多少对互作）② 强度（概率加权）③ 角色（sender/receiver/mediator/influencer，基于网络中心性）。

**为什么全细胞类型数据才适合做通讯**：通讯发生在**不同类型**细胞之间。只有 T 细胞时只能算 T 亚群间互作，丢失了"微环境→T 细胞"这条主线。方案：合并/换用含上皮、髓系、基质细胞的数据（如 GSE132465），或利用 GSE108989 中 CD45+ 全免疫组分。

### 面试自测题

**Q1：CellChat 推断出"MIF–CD74 在髓系→T 细胞间显著"，能说明什么、不能说明什么？**
> 答案要点：能说明——两类细胞分别高表达该配体/受体，且经置换检验显著高于随机背景，提示**潜在**通讯；不能说明——物理上真的接触、信号真的传递（空间位置未知）。表述："提示潜在的 MIF 介导的免疫抑制信号"，可补充"需空间转录组或实验验证"。

**Q2：为什么分析 GSE108989 这类 FACS 分选数据时 `population.size` 要设 FALSE？**
> 答案要点：该参数假设"各群细胞数反映体内真实比例"，用于校正细胞数多的群天然互作机会多。FACS 分选人为改变了细胞比例（比如富集 CD45+），比例失真，校正前提不成立，故设 FALSE 不做群体大小校正。全组织消化（未分选）数据才考虑 TRUE。

**Q3：免疫检查点通路（TIGIT、PD-1）在 CellChat 里属于哪类互作？分析时数据库要怎么选？**
> 答案要点：属于**细胞-细胞接触（Cell-Cell Contact）**类，不是分泌信号。如果只 subsetDB 选 "Secreted Signaling" 会完全漏掉检查点通路。要用完整 CellChatDB 或显式包含 Cell-Cell Contact。

### 常见报错

| 报错 | 原因与解决 |
|---|---|
| 安装 `sqjin/CellChat` 后与 Seurat v5 不兼容 | 旧仓库是 v1。改装 `remotes::install_github("jinworks/CellChat")`（v2）。 |
| `createCellChat` 报 metadata 行名不匹配 | meta 行名必须与表达矩阵列名（细胞 barcode）完全一致且顺序对应。 |
| NMF 依赖安装慢/失败 | NMF 依赖多属正常；Windows 上确保 Rtools；可换 `BiocManager::install("NMF")`。 |
| `computeCommunProb` 极慢 | 细胞数过多。小数据用 raw.use=TRUE；>3 万细胞考虑抽样或用 `type = "truncatedMean"` 加速。 |
| 气泡图报错/过宽 | L-R 对太多导致图巨大。先用 `signaling = c("MIF","TIGIT")` 限定通路，或用 `subsetCommunication()` 导表筛过再画。 |
| `future` 并行相关报错 | CellChat v2 用 future 框架，Windows 上 `plan(multisession)` 偶发问题；设 `future::plan("sequential")` 退化为串行即可。 |

## 模块 06：inferCNV 恶性细胞推断【可选·高阶】

### 核心概念

**CNV 推断原理**：肿瘤细胞的染色体片段扩增/缺失会导致该区域**整段基因的表达量系统性偏高/偏低**。inferCNV 把基因按染色体坐标排序，用滑动窗口（默认 101 个基因）平滑表达信号，再减去参考（正常）细胞的平均信号——剩下的"残差热图"上，成片的染色体臂级红/蓝条纹就是疑似 CNV。

**关键前提：参考细胞必须是基因组正常的细胞**。最常用同一肿瘤内的浸润免疫细胞（T/B/髓系）——它们和肿瘤细胞经历完全相同的实验流程，技术噪音可互相抵消。参考选错（比如混入恶性细胞）会把真 CNV 抵消掉。

**分辨率与局限**：只能看到大片段（染色体臂级）事件；是表达层面的**间接推断**，金标准是 WES/WGS；个别正常细胞（高增殖状态）也可能有假阳性。

### 面试自测题

**Q1：为什么 inferCNV 必须设参考细胞？选什么做参考最好？**
> 答案要点：inferCNV 是相对分析——观察组信号 = 观察组平滑表达 − 参考组平滑表达，没有参考就没有基线。最佳参考是同一病人的非恶性细胞（通常是免疫细胞）：基因组稳定 + 批次完全一致。不能用其他样本/其他研究的"正常细胞"随意拼，批次效应会被误判成 CNV。

**Q2：热图上上皮细胞群整体出现 18q 缺失条纹，生物学上意味着什么？**
> 答案要点：18q 缺失是结直肠癌经典事件（该区段含 SMAD4 等抑癌基因）。上皮群整体带这种染色体臂级 CNV、而参考免疫细胞没有 → 支持这群上皮细胞是恶性细胞；且 CNV 谱与 CRC 已知模式吻合，互为印证。

**Q3：为什么 GSE108989 不适合做 inferCNV？本模块怎么解决？**
> 答案要点：GSE108989 是分选富集的免疫细胞（主体 T 细胞），几乎不含上皮细胞——没有"疑似恶性"的观察对象，分析无从谈起。解决方案：换用含上皮细胞的全细胞类型数据集（如 GSE132465，SMC 队列，含上皮/基质/免疫全细胞），用其免疫细胞做参考、上皮细胞做观察组。

### 常见报错

| 报错 | 原因与解决 |
|---|---|
| 内存爆炸 / R 崩溃 | inferCNV 是三个模块里最吃内存的。6 万+ 细胞必须抽样（脚本默认每群抽 1500）；`num_threads` 降低；关掉其他程序。 |
| `CreateInfercnvObject` 报基因名不匹配 | gene_order 文件的基因名与矩阵行名命名体系不一致（如一个是 symbol 一个是 Ensembl ID）。统一用 gene symbol，且矩阵行名去重。 |
| 染色体名格式错误 | inferCNV 默认只认 chr1-22/X/Y（hg 坐标）。gene_order 里去掉 chrM、scaffold 等；确保格式为 "chr1" 而非 "1"（视版本而定，按报错提示调整）。 |
| JAGS / rjags 安装失败 | 只有 HMM=TRUE 才需要。新手用 HMM=FALSE（脚本默认），完全避开 JAGS。 |
| 热图上一片红/蓝无差异 | ① 检查是否误用了标准化数据（必须用原始 counts）；② 参考组和观察组是否填反；③ cutoff 设置是否过严导致基因太少。 |
| `EnsDb` 相关报错 | 确认基因组版本与数据比对版本一致：hg38 用 EnsDb.Hsapiens.v86，hg19 用 v75。 |

## 通用建议

1. **先跑通再理解**：脚本注释详尽，建议先完整跑一遍看图，再回头读概念；
2. **报错先查版本**：三个模块的报错 80% 与包版本有关（Seurat v4/v5、monocle3/CellChat 仓库选择），每个脚本开头都有版本兼容说明；
3. **展示原则**：跑通哪个讲哪个，理解多少展示多少，没跑通的部分面试不主动提（见 README 免责声明）。
